# Example Run

Read this only when the user asks to see an example. Notice the gate evidence, direct recommendation, and pass/fail test rather than copying the domain.

## Input

> Our weekly team retrospectives feel stale and nothing changes afterward.

## Phase 1 Excerpt

> **How might we turn an eight-person team's weekly retrospective into one observable improvement within the following week, without adding meeting time?**
>
> I read the problem as failed follow-through rather than an uninteresting meeting format. What observable result would make the next retrospective feel worthwhile?

After the user answers "one agreed action actually completed," the skill resolves the remaining gate evidence one question at a time, then offers distinct bets:

1. **Subtraction - One action:** End with exactly one owned action and open the next retro with evidence it happened. Bet: focus, not idea quality, is the bottleneck.
2. **Inversion - Start with evidence:** Begin each retro by reviewing the previous commitment; spend remaining time only after it is resolved. Bet: visible accountability changes behavior.
3. **Audience shift - Quiet voices first:** Collect anonymous observations before discussion and let quieter members rank them. Bet: missing input causes weak commitments.
4. **Constraint - Fifteen-minute retro:** Use five minutes for evidence, five for one bottleneck, and five for one experiment. Bet: the old format creates performative discussion.
5. **Combination - Retro as experiment review:** Phrase the action as a one-week hypothesis with a measure and owner. Bet: testable changes get completed more often than generic tasks.

The skill asks which bets resonate and waits. The user chooses options 1 and 5.

## Phase 2 Excerpt

**One owned action**

- **Value / feasibility / differentiation:** Makes follow-through visible with only a facilitation change; novelty is irrelevant.
- **Evidence / constraint / switch reason:** The user reports a recurring unowned backlog; choosing one action that matters is hardest; the team switches because this adds no tool or meeting time.
- **Must be true:** The team can choose one meaningful action. **Should be true:** An owner can show evidence within a week. **Might be true:** Anonymity improves the choice later.
- **Kill condition / cheapest test:** Run this with the eight-person team for two retros. Pass if both actions have an owner, deadline, and reviewed evidence; otherwise kill the bet.

**One-week experiment**

- **Value / feasibility / differentiation:** Connects each action to an outcome; requires a measurable signal but creates a learning loop.
- **Evidence / constraint / switch reason:** The same reported backlog supports the need; agreeing on a signal is hardest; the team switches to learn whether the action worked, not merely whether it closed.
- **Must be true:** The team can agree on one observable signal in five minutes.
- **Kill condition / cheapest test:** Run two retros. Pass if both produce a signal the team can review without debate; otherwise drop experiment wording.

**Status quo**

- **Value / feasibility / differentiation:** Requires no change and is fully feasible; offers no new value or differentiation.
- **Evidence / constraint / switch reason:** The current backlog is evidence against it; no credible switch reason exists.
- **Must be true:** Follow-through can improve without changing ownership or review.
- **Kill condition / cheapest test:** Audit the last four retros. Pass only if at least three actions had owners and reviewed evidence; otherwise reject the status quo.

**Recommendation:** combine one owned action with experiment wording. The reported backlog makes ownership the strongest available bet; the decisive trade-off is less discussion breadth for observable follow-through. Keep new tools and format rotation out of scope.

The skill asks the user to confirm this direction before drafting.

## Phase 3 Excerpt

# One-Action Retrospective

## Problem Statement

How might we turn an eight-person team's weekly retrospective into one observable improvement within the following week, without adding meeting time?

## Recommended Direction

The reported unowned backlog points to follow-through as the bottleneck. End each retro with one owned, one-week experiment and start the next retro with its evidence, trading discussion breadth for observable accountability.

## Key Assumptions To Validate

- [ ] One-action focus improves completion - run for two retros - pass if both actions have an owner, deadline, and reviewed evidence.

## MVP Scope

Use the existing meeting and tools for two weeks. Change only the output and the first five minutes of the following retro. Kill the direction if either retro lacks an owner, deadline, or reviewed evidence.

## Not Doing (And Why)

- New retrospective software - it cannot test whether ownership is the bottleneck.
- Rotating formats - novelty would confound the follow-through test.

## Open Questions

- Which completed-team-change signal is easiest to review without debate?
