# Variation Lenses

Read this only when Phase 1 directs you here. Select lenses that change who acts, what value is delivered, or what must be true. Replace weak variations rather than adding volume.

## Inversion

Reverse the default relationship, sequence, ownership, or business model.

- What if the user performed the system's work, or the system performed the user's?
- What if the last step came first?
- What if the beneficiary paid nothing and another participant paid?

## Subtraction

Remove the expensive or assumed center of the idea.

- What version has one capability, zero setup, or no new interface?
- Which bundled job can become a separate product?
- What remains when the obvious technology is unavailable?

## Constraint

Force a different mechanism with a hard boundary.

- Deliver value in one day, for ten users, or with no budget.
- Support only the hardest user or only the most frequent case.
- Make the solution work without a dependency the idea currently assumes.

## Audience Shift

Move the same job to a participant with different incentives or access.

- Who experiences the problem most intensely?
- Who controls the missing resource or decision?
- Which excluded audience would value a simpler version?

## First Principles

Separate observed facts from conventions, then rebuild from the facts.

1. List what direct evidence establishes.
2. Name the conventions the current idea inherits.
3. Remove one convention and derive a new direction.

## Structural Analogy

Borrow a mechanism from a domain with the same structure, not the same surface.

- Which field already coordinates the same incentives, trust, scarcity, or timing problem?
- What mechanism makes that system work?
- How would that mechanism translate without copying its presentation?

## Combination

Join complementary jobs only when the combination changes the core bet.

- Pair a high-value manual service with a narrow automation.
- Combine a distribution advantage with an existing commodity capability.
- Couple detection with the action that resolves what was detected.

## Scale Shift

Change scale far enough that a different architecture or behavior becomes rational.

- What works for one user but fails for a million?
- What becomes possible for a community but not an individual?
- What would a ten-times smaller promise make dramatically easier?
